# Room Planner — спецификация проекта

Веб-приложение для планирования ремонта комнаты: 3D-план с реальными размерами, расстановка мебели (в том числе готовых GLB-моделей), смета. Хостинг: GitHub Pages. Без бэкенда.

## 1. Цели

- Увидеть комнату в 3D по реальным размерам и проверить, что мебель помещается.
- Быстро переставлять мебель мышью и менять размеры.
- Подключать готовые модели (GLB) и приводить их к реальным габаритам.
- Вести список материалов и работ со сметой.
- Все данные проекта хранятся в одном JSON-файле, который легко читать и править вручную или с помощью ИИ.

## 2. Не цели (на старте)

- Нет аккаунтов, серверной части и синхронизации между устройствами.
- Нет фотореалистичного рендера (это задача для Blender).
- Нет поддержки закрытых форматов (.skp, .blend) напрямую — только через экспорт в GLB.

## 3. Стек

| Что | Выбор | Почему |
|---|---|---|
| Язык | TypeScript | Типизация, близко к C# |
| Сборка | Vite | Быстрый dev-сервер, простая сборка в статику |
| 3D | Three.js | GLTFLoader, DragControls/TransformControls, OrbitControls |
| UI | Vanilla TS + HTML/CSS (при росте — Svelte или React) | Минимум зависимостей на старте |
| Тесты | Vitest | Для геометрии и валидации сцены |
| CI/CD | GitHub Actions → GitHub Pages | Автодеплой при push в `main` |

Актуальные версии пакетов и Actions проверить при создании проекта.

## 5. Модель данных

Единицы в JSON — **миллиметры**. Внутри Three.js — метры (`utils/units.ts`). Система координат: Y — вверх, пол в плоскости XZ, начало координат в левом ближнем углу комнаты.

### 5.1. `project.json`

```json
{
  "version": 1,
  "name": "Моя комната",
  "room": {
    "width": 4200,
    "length": 5000,
    "height": 2700,
    "wallThickness": 100,
    "floorMaterial": { "color": "#b08a5b" },
    "wallMaterial": { "color": "#f2efe9" }
  },
  "openings": [
    {
      "id": "door-1",
      "type": "door",
      "wall": "south",
      "offset": 800,
      "width": 900,
      "height": 2100,
      "sill": 0
    },
    {
      "id": "window-1",
      "type": "window",
      "wall": "north",
      "offset": 1200,
      "width": 1500,
      "height": 1400,
      "sill": 900
    }
  ],
  "sockets": [
    { "id": "sock-1", "wall": "east", "offset": 1000, "height": 300 }
  ],
  "furniture": [
    {
      "id": "wardrobe-1",
      "catalogId": "wardrobe-basic",
      "position": { "x": 300, "z": 250 },
      "rotationY": 0,
      "size": { "w": 900, "h": 2100, "d": 500 },
      "color": "#ffffff"
    }
  ],
  "estimate": [
    {
      "id": "est-1",
      "category": "Материалы",
      "name": "Ламинат",
      "unit": "м²",
      "quantity": 21,
      "unitPrice": 0,
      "note": ""
    }
  ]
}
```

- `wall`: `north | south | east | west`; `offset` — расстояние от левого угла стены (если смотреть изнутри комнаты), мм.
- `position` — положение центра основания предмета, мм.
- `rotationY` — угол в градусах, шаг 90° по умолчанию, свободный поворот опционально.

### 5.2. `catalog.json`

```json
[
  {
    "id": "wardrobe-basic",
    "name": "Шкаф базовый",
    "category": "Хранение",
    "model": "models/wardrobe.glb",
    "defaultSize": { "w": 900, "h": 2100, "d": 500 },
    "source": "URL или автор",
    "license": "CC-BY 4.0"
  }
]
```

Если `model` пустой — предмет рисуется как параллелепипед по `defaultSize` (запасной вариант без GLB).

## 6. Функциональные требования

### MVP (этап 1)

1. Построение комнаты по `room` (пол, 4 стены, опционально потолок с переключателем).
2. Проёмы: двери и окна вырезаются в стенах (CSG или сегментированные стены).
3. Камера: орбита мышью, переключение «вид сверху» (2D-режим) / «перспектива».
4. Мебель — параллелепипеды по `size`, цвет задаётся.
5. Перетаскивание по полу, поворот на 90°, привязка к сетке (шаг настраивается, по умолчанию 50 мм).
6. Панель свойств выбранного объекта: позиция, размер, поворот, цвет.
7. Проверки: выход за стены, пересечение с другой мебелью, перекрытие проёма (подсветка красным).
8. Загрузка и сохранение проекта: `project.json` ↔ localStorage, экспорт и импорт файла.

### Этап 2

1. Загрузка GLB из каталога, автоматическая нормализация под `size` (масштабирование по bounding box).
2. Каталог мебели с поиском и добавлением в сцену.
3. Размерные линии (расстояния от мебели до стен, высоты).
4. Розетки и выключатели как отдельные объекты на стенах.
5. Текстуры пола и стен (паркет, плитка, обои) с масштабом в мм.

### Этап 3

1. Смета: таблица, итоги по категориям, автоподсчёт площади пола, стен и периметра для материалов.
2. Экспорт сметы в CSV.
3. Варианты планировки (несколько сценариев в одном проекте) и сравнение.
4. История изменений (undo/redo).
5. Скриншот сцены в PNG.

## 7. Нефункциональные требования

- Работает в современных Chrome, Firefox, Safari, Edge на десктопе; мобильные — просмотр.
- Первая загрузка до ~2 МБ без моделей мебели; модели подгружаются лениво.
- Все размеры в UI отображаются в мм (опционально см).
- Код типизирован, схема проекта валидируется при загрузке (понятные ошибки при кривом JSON).
- Никаких внешних сервисов и трекинга, данные остаются в браузере.

## 8. Деплой на GitHub Pages

### 8.1. `vite.config.ts`

Для репозитория `https://github.com/<user>/room-planner` сайт будет по адресу `https://<user>.github.io/room-planner/`, поэтому нужен `base`:

```ts
import { defineConfig } from 'vite';

export default defineConfig({
  base: '/room-planner/',
});
```

Имя в `base` должно совпадать с именем репозитория. Пути к моделям строить через `import.meta.env.BASE_URL`, а не от корня `/`.

### 8.2. `.github/workflows/deploy.yml`

```yaml
name: Deploy to GitHub Pages

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm
      - run: npm ci
      - run: npm test --if-present
      - run: npm run build
      - uses: actions/upload-pages-artifact@v3
        with:
          path: dist

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

В настройках репозитория: **Settings → Pages → Source: GitHub Actions**. Версии Actions проверить на момент создания.

### 8.3. Ограничения Pages

- Только статика, без серверного кода.
- Рекомендуемый размер репозитория до 1 ГБ, сайта до 1 ГБ, отдельный файл в репозитории не более 100 МБ.
- Публичный репозиторий отдаёт сайт бесплатно; приватный требует платного плана. Для личного проекта с реальными размерами квартиры лучше учесть, что публичный репозиторий означает публичные данные `project.json`.

## 10. Порядок работы с ИИ

- Источник правды — `project.json` и `catalog.json`: изменения плана делаются правкой этих файлов.
- Для правок кода передавать ИИ нужные файлы целиком (`room.ts`, `furniture.ts`, `schema.ts`) и формулировать задачу в реальных размерах («сдвинь шкаф на 200 мм от северной стены»).
- При добавлении GLB-модели заносить её в `catalog.json` с источником и лицензией.
- Для работы напрямую с репозиторием (чтение файлов, правки, запуск тестов) удобно использовать Claude Code.

## 11. Риски

| Риск | Что делать |
|---|---|
| Модели из интернета в произвольном масштабе | Нормализация по bounding box к `defaultSize` |
| Вырезание проёмов в стенах усложняет геометрию | На MVP стены сегментами вокруг проёма, CSG — позже |
| Тяжёлые GLB тормозят страницу | Ленивая загрузка, сжатие (Draco/meshopt), лимит на размер модели |
| Лицензии моделей | Поле `license` в каталоге обязательно |
| Публичный репозиторий раскрывает планировку | Не хранить адрес и личные данные в `project.json` |

## 12. Критерии готовности MVP

- Комната из `project.json` отображается в 3D с дверью и окном.
- Шкаф, кровать и стол можно двигать и поворачивать, и выход за стены подсвечивается.
- Проект сохраняется и восстанавливается после перезагрузки страницы.
- Сайт доступен по адресу GitHub Pages и обновляется после `git push`.
